## GIS区布局说明
GIS区必须保持“地图主画布 + 右上角渠段图例 + 左下角基础图例 + 底部动态水面线面板”的稳定结构，不得改动整体布局层级；手动拖动交界面时可改变布局，

闸门点位点击行为必须稳定触发下方双图表联动；


## 动态水面线区域说明
### 总体说明
动态水面线必须位于 GIS 区底部透明层内，支持时间步滑动/播放，x 轴刻度显示闸门名称，x 轴标题可留空，y 轴保留可读刻度并提供足够大的可视范围以保证曲线变化清晰可见；

### UI布局
动态水面线区域，“渠段”和“时间步”直接在“动态水面线右侧”，只保留一个“动态水面线”的区域标识字样；
图例居中，与动态水面线同行，尽量增大图表区域占比；
时间轴减小刻度、减小刻度与时间轴的距离，尽量缩小时间轴刻度及标签的空间占比；
动态水面线区域的图表应该允许重置视角，防止放大之后无法恢复。

# 数据管理
1. gates_mesh.csv为一个pivot格式文件，保存闸门与离散网格(input.txt和Gates.ini)之间的节点对应关系，只在初始化页面时读取一次，后续均调用这个数据。
2. gates_mesh.csv列标签为[id,x,y,z,type,gate_name]，其中id对应/mesh/input.txt中的第0列；x,y,z分别对应/mesh/input.txt中的1-3列，type对应/mesh/input.txt中的第4列；gate_name对应Gates.ini文件中的name，id对应/mesh/Gates.ini中的nIndex；
3. 渠底高程信息应该从gates_mesh.csv中获取，请参考ph中已有的gates_mesh.csv，根据Gates.ini和input.txt生成sj-zonggan-d0的gates_mesh.csv，并从gates_mesh.csv中获取高程提供给动态水面线
4. gates_mesh.csv中的闸门与Gates.ini中的闸门如果无法一一对应，就要更新，然后再画
5. 各区域涉及到渠道和闸门的曲线或gis图时，若 mesh 中缺失某节制闸，则自动桥接其前后闸门形成连续渠段。
6. 打开页面后，读取edges.csv中的信息，每个闸门的type信息只在初始化页面时读取一次，后续均调用这个数据
7. 关于edges.csv的说明：
```
该文件的`source`和`target`代表不同的闸门对象，调度模型中应该取这两列元素的并集，每个元素都保持唯一。

1. 该文件暗含了闸门的类型并保存了调度单元和闸门之间的拓扑关系。

2. source一定为节制闸，target有可能是节制闸或分水闸；（通过该定义隐式设定了闸门的类型）

3. 所有的渠段都是由2个以上的节制闸组成，以上游节制闸(`source`)表示。末尾节制闸作为`source`时，其`target`为`-1`.

4. 当`ConnectionType`为`indirect`时，表明`source`和`target`之间是非直接连接，存在中间节点（渠段内部的分水闸、入流、泄水闸等等）。`ConnectionType`右侧的列均表示的是`source`的属性。`m`和`width`表示渠段的横断面参数，只有`ConnectionType`为`indirect`时生效。

5. 当`ConnectionType`为`direct`时，表明`source`和`target`之间是直接连接，此时的`target`（渠段内部的分水闸type=2、虚拟入流type=1、泄水闸type=3,虚拟出流type=6等等）隶属于`source`作为上游节制闸的渠段。`ConnectionType`右侧的列均表示的是`target`的属性。`m`和`width`表示渠段的横断面参数，此时不生效。

6. `canal`代表的是`source`所属的渠道名称；

7. `id`是`source`的唯一标识，程序中会对所有闸门进行重新标号；

8. `delaytime`仅存在于`ConnectionType`为`indirect`的行，表示水流从`source`运动到`target`的时间。单位为分钟(`min`)。

9. `type`标识`source`或者`target`行的边界条件类型。

   - 0-水源
   - 1-入流
   - 2-出流
   - 3-泄水
   - 4-节制
   - 5-地表径流(`surface flow`)
   - 6-损失
   - 7-生活用水，应优先保障

10. 分水闸的配水需求可以通过设置`maxFlow=minFlow`来实现。
```






# 必须遵守的要求
1. 页面布局不变，GIS 图可以适当变化
2. 如果mesh中没有edges,csv中的某个节制闸，可以将缺失节制闸前后的闸门直接连接起来作为渠段，使得gis中的渠段颜色渲染正确
3. 图表的x轴要用时间步序号：起止时间和时间步长要在渠段图表和闸门图表文本后显示，通过最开始的两个时间步的时间戳差距判断
4. 路径只是默认路径，不应该影响启动，如果找不到也应该在页面上红字提示

# 图表X轴回归禁令

1. 只要 `gate_curve_map.html` 和 `standalone_charts.html` 存在同类图表，就严禁只修一边；必须先读取已正确的一侧，再把同一套 X 轴数据契约同步到另一侧。
2. 涉及图表 X 轴、时间对齐、插值、hover 文案的修改，严禁只看代码形状判断正确；必须先用真实案例文件核对一次时间范围、数据源路径、对象名匹配关系。
3. 如果模拟数据时间轴和实测数据时间轴不重叠，优先判断为“数据源选错”或“文件切换逻辑错误”，严禁先归因到插值公式或 Plotly 渲染。
4. 如果主页面 `http://127.0.0.1:8610/gate_curve_map/gate_curve_map.html` 中对应图表行为已经正确，修改独立页 `standalone_charts.html` 时必须以主页面当前实现为唯一参照，不能重新发明一套 X 轴逻辑。
5. 只要采用“先按时间戳匹配，再投影到模拟步序号”的方案，就必须同时满足：
   - 匹配基准先是同一时间轴上的时间戳
   - 绘图坐标再是模拟值的步序号或对应插值坐标
   - 非离散实测点必须插值得到 X 坐标后再入图
   - 轴标题和 hover 文案必须明确写清“模拟步序”与“时间”
6. 任何图表修复完成后，提交前至少做一次针对真实 case 的自检，最少确认这四项：
   - 当前实际加载的是哪一个模拟文件
   - 当前实际加载的是哪一个实测文件
   - 两者时间范围是否重叠
   - 主页面与独立页的 X 轴行为是否一致
